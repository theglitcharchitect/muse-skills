# Build checklist: component → technique

1. **Case-file desk depth**: `perspective` on desk container + `transform-style: preserve-3d` inner + `translateZ()` per layer; numeral background layer at `translateZ(-400px) scale(1.4)` (math: `1 + d/perspective`); keep 3D range modest (~hundreds of px against ~1000px perspective); no `overflow: hidden`/`filter`/`clip-path` ancestors.
2. **Chapter cards pull-forward**: `position: sticky; top: calc(var(--i) * 24px); min-height: 100svh` (each new card slides over pinned ones; slivers of buried cards visible as the pile edge); scale-down refinement via rAF loop (all browsers) or `view()` exit ranges (Chrome/Safari); reference Bramus stacking-cards demo and animation-handbook.
3. **Oversized sticky chapter numbers in background parallax**: sticky threshold (e.g. `top: 12vh`) + `view()` `exit` animation-range drift slower than foreground + `translateZ(-d)` depth with scale compensation; Firefox fallback is IO-driven translate; base is static oversized numerals.
4. **Vertical evidence spine**: sticky line always rendered (static baseline); progress fill via `scroll(root)` driving `scaleY` inside `@supports`; Firefox path is the rAF spine-progress function writing `transform` only; optional IO scrollspy for current-chapter highlight.
5. **Strongest figure revealed per chapter**: IO `.is-in` reveals (transform/opacity transitions gated on `no-preference` + `.js` guard), or pure-CSS `view()` entry ranges where supported; `@property` counters for animated numbers with no JS.
6. **Global motion engine**: exactly one passive `scroll` listener + one rAF scheduler (reads before writes; no `getBoundingClientRect` in the handler; re-cache on resize); compositor-only properties; `will-change` pre-warmed one viewport ahead, removed on settle; `content-visibility: auto` + `contain-intrinsic-size` on chapters (spine and JS-measured elements outside them); `svh`/`dvh` units, never raw `100vh`.
7. **Fallback layers, in order**: (1) base CSS is a complete static page, flat stacked cards, no hidden states; (2) `@supports (animation-timeline: scroll())` adds scroll-driven enhancements; (3) `@media (prefers-reduced-motion: no-preference)` adds parallax, 3D, scale reveals (`.js` guard nested inside); (4) JS checks `CSS.supports('animation-timeline','scroll()')` + device hints (`saveData`, `hardwareConcurrency`, `deviceMemory`) to decide whether the rAF loop registers at all, otherwise the page stays the flat-card stack; (5) `prefers-reduced-motion: reduce` flattens transforms, zeroes durations, skips the rAF loop, spine becomes a static indicator.
8. **Platform traps to verify before shipping**: Firefox stable (IO + rAF path renders everything statically); iOS Safari (sticky numerals/spine with `overflow: visible` ancestors; `dvh`; no fixed `backdrop-filter` bars; never write `scrollTop` during momentum); anchor links and find-in-page with `content-visibility: auto`; no mandatory vertical snap hijacking keyboard scrolling.
9. **Pre-ship verification**: test matrix Chrome / Safari (current + one old iOS) / Firefox stable / reduced-motion ON / JS disabled / low-end Android (flat-card path); DevTools paint-flashing and frame meter across a full scroll; no layout-property animation in traces; sane layer counts on mobile; zero motion libraries; JS motion code target under 3KB.
